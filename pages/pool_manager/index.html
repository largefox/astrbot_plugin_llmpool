⚙️ 调度策略与超时控制

▼

控制模型选择策略、失败切换、以及各级超时限制。

单次请求在组内最多尝试的节点数（建议 5 次，防止全量死循环重试）
当前成员报错或超时时，在同一次请求内继续尝试下一成员
所有成员均失败时返回空回复，不向群聊喷出英文报错红字
失败后重试下一节点前的最小等待秒数（默认 0 不等待）
同组内失败时按权重重新选择节点，而非立即跨组回退
每个池成员非流式调用的超时限制（默认 50 秒，容忍长文本生成并防止死节点卡死）
等待首个 Token 的阶梯基准时间（默认 26s），超时立即切换下一节点
输出过程中单次 chunk 停滞超过该秒数即判定上游断流，主动截断报错（默认 10s）
整轮调用的全局总耗时硬上限（默认 120 秒）。时间吃紧时自动跳过中间慢组，顺序快连保底组抢答

🛡️ 熔断冷却与错误容忍策略

▼

控制各类错误触发熔断的阈值与冷却时长，平衡快速故障转移与避免偶发抖动误杀。

触发熔断后的常规封锁时长（默认 1800s / 30 分钟）
上游返回 429 限频时的封禁冷却时间（默认 1800 秒）
短时间内优先分流至同组其他模型（防 429）；设为 0 不限制
每天该整点自动唤醒解冻深度休眠节点（默认 2 点）

精细化错误容忍次数 (Allowed Fails)

建议 0 次（一旦 429 立即短时冷却）
连续超时达到该次数后进入冷却
400 请求错误容忍次数
激进节点容忍的连续失败次数（默认 5 次），达到阈值才熔断

⚡ 延迟对冲与拥堵提权

▼

防长尾延迟与高峰拥堵的自动化高级调度策略。

当主节点响应超过对冲阈值时，自动拉起同组备选节点并发竞速，取最先返回者
主节点请求发出后超过此秒数未返回时触发并发对冲（默认 24.0 秒）
当主模型组大面积熔断或平均延迟严重恶化时，自动将后备保底层顺序向下提权为主力（保留轻量探针探活）
主模型组可用节点前几名平均耗时超过该秒数即判定进入高峰拥堵（默认 40.0 秒）

📖 欢迎使用 LLM 模型池

把你的模型当成人才来管理：选人、考核、淘汰、提拔，全部交给算法。

第一步：把 AstrBot 中已配置的对话模型导入模型池。

导入后可在「🎛️ 模型池配置管理」中调整分组、排序和高级参数。

也可以跳过导入，稍后手动添加成员。

⚙️ 高级配置（自行设置）

以下配置不影响首次使用，随时可在「🎛️ 模型池配置管理」中调整：

  • 模型组与回退链 — 为成员设置 tier1/tier2/tier3 分组，配置降级顺序
  • 专用节点池 — 独立的轻量判定/意图识别池
  • 调度策略与超时 — 负载均衡、熔断冷却、延迟对冲等

默认配置已可正常工作，进阶调优随时再做。

✅ 最后一步：在 AstrBot 中选择模型池

需要在 AstrBot 管理面板中将 llm-pool 设为对话模型：

操作步骤：

  1. 在 AstrBot 管理面板左侧导航栏中点击「配置文件」
  2. 找到「对话模型」或「回退对话模型」
  3. 选择 llm-pool 作为模型
  4. 点击保存

专用节点池（如 light_llm_pool）也可在需要时选择。
