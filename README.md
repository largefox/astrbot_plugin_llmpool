# LLM 模型池

> 把大模型当牛马管！让你的模型背上 KPI：能者上、庸者下，慢的优化、崩的开除！  
> 组间竞争、梯队化管理、末位淘汰、KPI 可视化，让你的 bot 用上最卷的模型梯队。

## 敝插件能做什么

| 功能点 | 介绍 |
|---|---|
| 🏢 **末位淘汰** | 慢的、爱报错的节点自动熔断停职，关小黑屋冷静反省后再复职 |
| 🏇 **组间竞争** | 攻坚主力、中流砥柱、保底兜底多梯队同台竞技，谁行谁上，优胜劣汰 |
| ⚡ **延迟对冲** | 主节点敢磨洋工？立刻拉起备用节点并发抢跑竞速，谁先交卷算谁的 |
| 📈 **拥堵提权** | 业务高峰主力组扛不住大面积阵亡时，自动把后备梯队火线提拔顶上 |
| 🌐 **对外承接业务** | 内置标准 OpenAI 兼容服务（默认端口 5120），一键将模型池能力共享给其他程序 |
| 📊 **KPI 看板** | 24h 可用率、延迟、成本下渗、摸鱼工伤与节点 ROI 全维度可视化 |
| 🏕️ **专用编制** | 轻量判定、意图识别单独开小灶搞外包团队，绝不挤占主力编制 |

**能者上、庸者下，低效节点自动优化，帮你的 bot 降本增效！**

```text
业务请求
  -> AstrBot
  -> llm-pool (虚拟路由总监)
      -> 攻坚克难第一梯队 (tier1)   ← 性价比最高、最能卷的上（默认全员一梯队，激发狼性）
        -> LLM-A / LLM-B / LLM-C
      -> 中流砥柱第二梯队 (tier2)   ← 随时准备补位顶上
        -> LLM-D / LLM-E
      -> 后备骨干保底梯队 (tier3)   ← 兜底扛雷不翻车
        -> LLM-F
```

## 工作原理

插件不修改 AstrBot 内核，只注册并维护一个稳定的虚拟“牛马总监”模型（默认 `llm-pool`）。AstrBot 以为自己在调用一个老实干活的模型，实际上背后是一整支随时待命、末位淘汰的模型军团：

- 任务派发、轮询抢跑、权重核算、超时考核、冷却停职、故障甩锅转移，全部由插件自动搞定
- 池成员必须是 AstrBot 中已配置好的真实模型下属
- 插件自身不持有任何上游 API Key（零风险，全靠下属打工）

### 专用节点池（独立外包小分队）

除主模型池外，还可以开多个**专用节点池**（如轻量判定池、意图识别池、语音识别池等），每个池独立拥有：

- 自己的 Provider ID、分组名、虚拟模型名
- 严格组隔离（专职专用，不跨组回退，绝不污染主链编制）
- 独立的调度策略、超时、最大尝试次数

专用节点池独立于主链梯队，专事专办，不参与向下击穿。

## 核心机制

### 派活机制（调度策略：谁先上）

| 策略 | 说明 |
|---|---|
| `usage-based-routing-v2` | 能者多劳，并发负载与权重综合排期（默认推荐，最懂排班） |
| `least_busy` | 纯最闲优先，谁手头活少先派给谁（最低并发优先） |
| `latency_based` | 手脚麻利优先，谁响应快谁先上（最低延迟优先） |
| `weighted_random` | 按职级权重随机抽奖派单 |
| `round_robin` | 排排坐吃果果，顺次轮流接单 |
| `ordered_failover` | 长幼有序，始终优先列表靠前的核心骨干 |

### 绩效考核（什么时候淘汰开除）

- **报错或超时** → 扣除绩效进入冷静冷却期，期间暂停派活
- **限流 / 欠费 (429)** → 判定被上游风控封停，按限流冷却时长严格关小黑屋
- **常规服务端错误** → 按常规熔断时长暂停接单反省
- **上游 502 / 彻底死亡** → 判定严重工伤，深度休眠至次日凌晨 02:00 自动解冻复查
- **全员阵亡（所有节点都在冷却）** → 触发强制抢救机制，允许一次全员复活尝试，杜绝摆烂卡死
- **连续失败容忍度独立核算**：限流 / 超时 / 400 / 激进抢跑节点各自拥有独立容忍额度，奖惩分明

### 组内加权重试 (Weighted Failover)

开启后，同梯队节点失败时不再死板按列表顺序死磕，而是**在组内按权重重新抓壮丁**，把流量压力均匀分摊到同组的多个区域、多个 Key 上，杜绝单点暴毙。

### 高级调度

- **延迟对冲赛马 (Hedging)**：主节点响应超时、疑似磨洋工摸鱼？立刻唤醒同组备选并发赛马，谁交卷快算谁的，慢的直接取消
- **拥堵提权 (Congestion Promotion)**：高峰期主力组集体堵死或大面积阵亡时，自动把后备梯队火线提拔为主力干活
- **激进抢跑模式**：专为免费 / Flash / 白嫖节点打造！0 成本大胆抢答，超时敏锐熔断、解封宽松快速，最大限度榨干免费羊毛

## 快速上手

1. 安装并启用插件。
2. 打开插件的**可视化页面**，首次进入会自动弹出使用指引。
3. 在「🎛️ 模型池配置管理」点击 **📥 导入 Provider** 一键导入 AstrBot 已配置的对话模型，或手动 **➕ 添加成员**（支持下拉选择或直接输入自定义 ID）。
4. （可选）为成员设置模型组（如 `tier1`、`tier2`、`tier3`），拖拽 ⠿ 手柄可任意调整梯队与顺序。
5. （可选）在「🔄 跨组回退链」配置梯队降级顺序（如 `tier1 → tier2 → tier3`）。
6. 点击 **💾 保存全部配置**。
7. 进入 AstrBot 管理面板的**提供商设置**，在**对话模型**或**回退对话模型**中选择 `llm-pool`。

> 💡 `llm-pool` 是虚拟路由入口，不需要填写 API Key、API Base URL，也不需要手动获取模型列表。

### 🌐 对外承接业务（OpenAI 兼容 API 服务）

不仅可以给当前 AstrBot 的 Bot 使用，还可以直接启动一个独立的 **OpenAI 兼容 HTTP 服务**，让你的外部程序（如 NextChat、ChatBox、Open WebUI、Cursor、Continue、各种自动化脚本等）直接调用这套强大的模型池：

1. 打开插件的**可视化页面**，在「🎛️ 模型池配置管理」下滑至「🌐 对外 OpenAI 兼容服务」。
2. 勾选 **开启外部 OpenAI 兼容服务**，按需填写监听端口（默认 `5120`）和认证密钥（可选）。
3. 点击 **💾 保存全部配置**，服务即刻在后台热启动。
4. 外部程序接入配置：
   - **API Base URL**：`http://<服务器IP>:5120/v1`（末尾带 `/v1`）
   - **API Key**：根据你在插件中设置的密钥填写（若留空则免密调用）
   - **Model**：填写 `llm-pool`（默认虚拟模型），或填写你配置的专用节点池模型名称（如 `light-pool-router`）
5. 支持的标准接口：
   - `POST /v1/chat/completions`（完整支持流式 SSE 和常规非流式响应）
   - `GET /v1/models`（拉取可用模型列表）
   - `GET /health`（服务探活与健康检查）

> 🚀 **红利共享**：外部程序的请求同样完整享受模型池的**组间竞争、自动熔断降级、延迟对冲赛马、并发负载均衡**，并且所有调用也会记录到插件的 KPI 看板中！

### 配置专用节点池

1. 在「🔑 专用节点池」中添加一个池，设置 Provider ID、分组名、模型名。
2. 在模型池成员中，为该分组添加真实 Provider。
3. 在 AstrBot 中即可选择该专用池的 Provider ID 作为特定场景的模型入口。

### 配置导入导出

- **导出**：点击配置页顶部 **📤 导出**，下载 `llm_pool_config.json` 完整配置快照
- **导入**：点击 **📥 导入**，选择之前导出的 JSON 文件，确认后覆盖当前配置
- **清空 / 重置**：在「⚙️ 插件管理」标签页可清空成员或一键重置为默认配置
