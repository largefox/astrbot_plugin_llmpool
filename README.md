# LLM 模型池

>  
> 把 LLM 们当成人才管理，搞末位淘汰、组间竞争、KPI监控，将低效节点优化掉，帮你的 bot 降本增效
> 

## 敝插件能做什么

| 功能点 | 介绍 |
|---|---|
| 🏢 **末位淘汰** | 慢的、爱报错的节点自动熔断调离，冷静反省后再复职 |
| 🏇 **组间竞争** | 主力、后备、保底多梯队同台竞技，谁行谁上，优胜劣汰 |
| ⚡ **延迟对冲** | 主节点磨洋工？立刻拉起备胎并行抢答，谁能干谁灭火 |
| 📈 **拥堵提权** | 高峰期崩盘时，自动把后备梯队火线提拔成主力 |
| 📊 **KPI 看板** | 24h 可用率、延迟、成本下渗、节点 ROI 全维度可视化 |
| 🏕️ **专用节点池** | 轻量判定、意图识别单独开小灶，不占主力编制 |

**能者上、庸者下，低效节点自动优化，帮你的 bot 降本增效。**

```text
请求
  -> AstrBot
  -> llm-pool (虚拟路由入口)
      -> 攻坚克难梯队 (tier1)   ← 性价比最高的上（默认全员都加到第一梯队，激发狼性）
        -> LLM-A / LLM-B / LLM-C
      -> 中流砥柱梯队 (tier2)   ← 随时准备补位
        -> LLM-D / LLM-E
      -> 后备骨干梯队 (tier3)   ← 兜底不翻车
        -> LLM-F
```

## 工作原理

插件不修改 AstrBot 内核，只注册并维护一个稳定的虚拟模型（默认 `llm-pool`）。AstrBot 以为自己在调用一个模型，实际上背后是一整支模型梯队：

- 选择、轮询、加权、超时、冷却、故障转移，全部交给插件完成
- 池成员必须是 AstrBot 中已配置好的真实模型
- 插件自身不持有任何上游 API Key

### 专用节点池

除主模型池外，还可以开多个**专用节点池**（如轻量判定池、意图识别池、语音识别池等），每个池独立拥有：

- 自己的 Provider ID、分组名、虚拟模型名
- 严格组隔离（不跨组回退，绝不污染主链）
- 独立的调度策略、超时、最大尝试次数

专用节点池独立于主链梯队，可以不参与向下击穿。

## 核心机制

### 调度策略（谁先上）

| 策略 | 说明 |
|---|---|
| `usage-based-routing-v2` | 并发负载与权重综合调度（默认推荐） |
| `least_busy` | 纯最闲优先（最低并发） |
| `latency_based` | 纯延迟优先（最快响应） |
| `weighted_random` | 按权重随机 |
| `round_robin` | 顺次轮询 |
| `ordered_failover` | 始终优先列表靠前成员 |

### 绩效考核（什么时候淘汰）

- 报错或超时 → 进入冷却，期间不再派活
- 限流 / 欠费（429）→ 按限流冷却时长封禁
- 常规错误 → 按常规熔断冷却时长封禁
- 上游 502 / 死亡 → 深度休眠至次日 02:00 自动解冻
- 所有节点都在冷却 → 允许一次完整重试，避免池永久卡死
- 连续失败次数可分类配置（限流 / 超时 / 400 / 激进节点各自独立）

### 组内加权重试 (Weighted Failover)

开启后，同组节点失败重试时不再死板按列表顺序，而是**按权重随机重新选择**，把压力均匀分摊到同组的多个区域 / 多个 Key 上。

### 高级调度

- **延迟对冲赛马 (Hedging)**：主节点响应超过阈值时，自动拉起同组备选并发竞速，取最快返回
- **拥堵提权 (Congestion Promotion)**：高峰期主组慢死或大面积熔断时，自动把后备保底组顺序提权为主力
- **激进抢跑模式**：给免费 / Flash 节点开启，快速试探抢答，超时敏锐熔断、快速宽松解封

## 快速上手

1. 安装并启用插件。
2. 打开插件的**可视化页面**，首次进入会自动弹出使用指引。
3. 在「🎛️ 模型池配置管理」点击 **📥 导入 Provider** 一键导入 AstrBot 已配置的对话模型，或手动 **➕ 添加成员**。
4. （可选）为成员设置模型组（如 `tier1`、`tier2`、`tier3`），拖拽 ⠿ 手柄可调整优先级。
5. （可选）在「🔄 跨组回退链」配置降级顺序（如 `tier1 → tier2 → tier3`）。
6. 点击 **💾 保存全部配置**。
7. 进入 AstrBot 管理面板的**提供商设置**，在**对话模型**或**回退对话模型**中选择 `llm-pool`。

> `llm-pool` 是虚拟路由入口，不需要填写 API Key、API Base URL，也不需要手动获取模型列表。

### 配置专用节点池

1. 在「🔑 专用节点池」中添加一个池，设置 Provider ID、分组名、模型名。
2. 在模型池成员中，为该分组添加真实 Provider。
3. 在 AstrBot 中即可选择该专用池的 Provider ID 作为特定场景的模型入口。

### 配置导入导出

- **导出**：点击配置页顶部 **📤 导出**，下载 `llm_pool_config.json` 完整配置快照
- **导入**：点击 **📥 导入**，选择之前导出的 JSON 文件，确认后覆盖当前配置
- **清空 / 重置**：在「⚙️ 插件管理」标签页可清空成员或一键重置为默认配置
